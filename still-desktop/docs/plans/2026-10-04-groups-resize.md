# ver0.12 — Still-Chrome layout, safe resizing and Groups

The user asked to return to the working Still-Chrome panel, remove Still bookmarks, ensure resizing works, add customizable Groups, and allow widget overlap without a blank browser.

Restore the Still-Chrome footer and bottom-right resize handle, plus the original spacing from the saved release change. The native Chrome host ends above a 34px footer so it cannot cover the 32px grip. Keep the saved sidebar collapse option and 80% Lecture control. Remove Still's duplicate URL/bookmark UI; Chrome's own address bar/bookmarks remain. Existing saved URLs and legacy bookmark data remain compatible.

Computer Use found multiple Still versions running. Native recovery used only the saved widget ID and shared Chrome profile, so a different Still owner could recover and hide the same window. An isolated real-Chrome regression reproduced this. Scope native properties to the process and owner HWND plus widget ID. Each owner keeps its own Chrome window. No SetParent, global topmost or profile copying is used.

Groups are movable/resizable tray widgets. Each stores a custom title and a list of named HTTPS resources with custom text/emoji icons. Add, edit, remove and reorder resource entries. Clicking a resource appends a fresh Browser widget with its own ID, instance number, title, URL and placement near the visible canvas; it never calls the existing-tab navigation command. All cards may overlap. Chrome visibility depends on the active workspace/dialog state, not rectangle intersections, dragging, clipping or minimum size. Native minimum window dimensions may overflow a smaller panel.

Tests first fail for missing Group support, distinct Browser instances and owner recovery. They then cover persistence, empty lists, title/URL normalization, independence after duplication, named Browser creation, unchanged existing browsers, and separate Chrome windows for two owners sharing widget IDs. The native harness pumps messages while closing Chrome, matching the running Tauri event loop. Desktop checks use Computer Use to verify real pointer dragging and Group interactions. Full signed-in university/video/extension acceptance remains outside these local checks.

Verified on 4 October 2026: TypeScript checks, all 29 frontend tests, all 13 Rust unit tests, the explicit real-Chrome smoke test, Vite and the Windows release build passed. The desktop check dragged the restored Browser corner from (760, 664) to (938, 746); both the card and Chrome resized, and Chrome remained visible over neighboring widgets. A saved Engineering Group opened its Lecture resource as a new named Browser widget with a separate Chrome window displaying example.com; the original Google Browser stayed intact. Moving the new widget also moved Chrome.

The isolated web preview verified adding two resources, editing names and icons, changing order, opening separate Browser instances, reload persistence and removing a Group entry without closing the Browser it had created. Still's bookmark buttons are absent. Desktop testing used separate WebView storage and did not replace the user's saved layout.
