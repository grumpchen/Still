# ver0.14 — reusable groups in the widget tray

The user requested a named tray button for groups such as CHEM111, with expand/collapse and the ability to add widgets again. They confirmed that groups should support any widget type plus website links.

Each workspace now has a saved group library independent of its Group card instances. New groups appear in that workspace's top tray immediately. Renaming a group updates its tray label and linked cards. Expanding the button reveals reusable widget entries, course links, Add widget, Add link, Edit and Open group. Each click or drag creates a fresh independent widget. Website links create separate Browser widgets with the saved URL. Saved widget entries store type, display name and icon; each new instance starts with that widget's defaults and saves its own state in the canvas. Group nesting is excluded.

Closing or dragging a Group card back to the tray removes only its card instance. Its tray collection stays available. Open group or dragging its named tray button adds a new Group card. Remove group deletes that collection and linked Group cards, keeps already opened widgets and supports the existing Ctrl+Z undo. Group expansion, entry order, names, icons, links and widget types are saved. Libraries belong to their workspace; duplicating a workspace gives independent group definitions and cards.

The existing version-4 workspace format gains backward-compatible optional group data. On load, old Group cards migrate into saved definitions without changing their links, positions or sizes. Parsing normalizes invalid entries. The original browser native code, BrowserWidget, visibility predicate, adapter and shortcut code are preserved from ver0.13.

Tray HTML drags also participate in the existing obscured-widget flag. This hides the native Chrome overlay during the drag and disables iframe pointer interception so the workspace receives the drop, then restores the normal presentation after drop or drag end. The final preview drag created a fourth independent Lab notes instance and cleared the drag flag afterward.

Verification: four new lifecycle and migration tests were observed failing before implementation, then passed. The complete frontend suite has 33 passing tests, including previous browser, layout and shortcut regressions. TypeScript passes. Browser preview checks covered naming CHEM111, creating a Lab notes entry and Lecture link, opening multiple independent Notes instances, closing the card while retaining the tray button, reopening the card, collapse persistence across reload and dragging a saved Notes entry into the workspace. Native Chrome resizing remains the previously deferred user acceptance; this release makes no new claim about that issue.

Final verification: the full frontend suite passed again after the tray-drag change; all 11 Rust unit tests passed (the explicit Chrome GUI smoke test remained ignored). The production Tauri build completed for 0.14.0. Preview console inspection returned no warnings or errors. Byte comparisons against the ver0.13 source archive confirmed unchanged BrowserWidget, chromeOverlay.ts, chromePanel.ts, native chrome_overlay.rs and shortcuts.rs.
