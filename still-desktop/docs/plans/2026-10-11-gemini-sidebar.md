# Still AI assistant

Still AI is one chat panel available from the sidebar. It supports Gemini and OpenAI API models. The selected model is shown in the composer footer and its provider/model preference is saved locally. API keys stay in Rust memory until Still closes; they are never saved to layouts, frontend storage, chat history, or logs. `GEMINI_API_KEY` and `OPENAI_API_KEY` can initialize their respective providers at launch.

## Use

1. Open **AI assistant** from the sidebar. Open the settings button, choose Gemini or OpenAI, and connect that provider's API key. Still remembers connected keys in Windows Credential Manager on this device. Gemini keys come from Google AI Studio. OpenAI API access requires a separate API key and is billed independently of a ChatGPT subscription.
2. Pick an available model in the selector at the bottom of the chat. The choice is remembered locally across workspace changes and restarts.
3. Chat normally to ask questions or request a layout. Still always sends workspace dimensions, widget names, IDs, geometry and minimum sizes so the assistant can propose a layout. The proposal is validated and shown for review; **Apply layout** changes positions and **Undo layout** restores the previous state.
4. Type `@` to open a picker containing all workspace widget names. Select one or **All widgets** to quickly point to relevant widgets; repeated `@` mentions can add several. The assistant can use supported data from current workspace widgets without explicit selection. Notes and timetables share bounded text/entries; Focus shares timer state; other widgets provide metadata. When exactly one attached app, calculator or Files widget is selected, an optional per-message toggle can include its visible screenshot with Gemini or OpenAI. The selected model must support image input.
5. Use ordinary wording such as **make notes widget**, **build a Focus widget**, or **create Notes named Revision with text about chemistry**. Simple gallery commands run locally; named widgets and generated note text can use the selected AI model. The model receives the full built-in catalogue even when no widgets are open. Vague edit requests are stopped locally and ask what change is wanted; if the model asks a clarification question alongside an action, Still discards that action. Requests outside the local wording rules can offer validated actions for review, and clarifying questions remain normal chat replies.
6. Still AI can also edit widget names, tag colors, Notes text and Timetable entries using current workspace data; toggle the Clock plugin on eligible widgets; add or remove the built-in Stack and Layout sidebar plugins; and rename the current workspace. Use `@` when you want to quickly identify a specific widget; it is not required for content edits. Layout responses remain proposals with an explicit Apply step.

Each model response labels its intent as chat, clarification, workspace action, or layout. Chat and clarification remain normal freeform conversation, and any accompanying workspace operations are discarded. Workspace actions are checked against the request and require on-screen review when the intent is uncertain; layout remains a separate proposal.

The browser preview exposes the UI but does not send AI requests or accept keys. Native transport requires the trusted main webview; remote child webviews cannot access AI commands. Messages and proposals live in memory for the current workspace session. Switching workspaces clears them; closing/reopening the assistant in the same workspace retains them. No AI requests run automatically.

## Safety and limits

- Tauri uses fixed provider HTTPS endpoints, no redirects, bounded requests/responses, and provider-specific errors. It does not accept arbitrary base URLs.
- Widget text, names, images and model replies are untrusted data. The assistant can chat, read supported current workspace widget data, propose/apply a validated layout, create built-in widgets, reopen saved tray items, minimize/restore cards, edit supported widget fields, manage built-in plugins, rename the current workspace, remove named or all canvas widgets, save reusable shortcuts, and start timers. Saved app shortcuts require confirmation before opening. Removing named or all canvas widgets, deleting the active workspace, and clearing the tray require confirmation and can be undone; Still will not delete the final workspace. It cannot install third-party plugin code or execute arbitrary code outside Still.
- One assistant request can create or open at most 10 items total, can edit or change plugins on at most 10 targets, and a workspace cannot exceed 100 widget cards through assistant actions. Oversized requests are rejected locally or at the response boundary before workspace updates. A rejected or over-cap batch leaves the workspace unchanged.
- Creating widgets supports an optional name up to 60 characters. New Notes widgets can include initial text up to 12,000 characters. Indirect or differently interpreted requests require review of the concrete actions before applying them. Ordinary writing and explanation requests do not run local widget commands just because they mention an action word.
- Layout proposals must include every expanded widget exactly once and pass ID, integer geometry, minimum size, edge, overlap, workspace fingerprint and canvas-size checks before application.
- Supported data from current workspace widgets is sent with assistant requests so Still can answer questions and make requested edits; `@` is an optional quick-selection hint. Attached native windows and file contents are not read except when the user explicitly enables screenshot sharing for the current message and an eligible visible widget.
- OpenAI model discovery filters the account's available models to chat-capable `gpt-` IDs. Image input availability depends on the selected model. Secure credential storage depends on Windows Credential Manager being available on the device.

## Verification

Run `pnpm check`, `pnpm test`, and `cargo test --manifest-path src-tauri/Cargo.toml assistant -- --test-threads=1`. Native AI requests require a user-provided provider key and should be tested manually on Windows; automated tests use local mock HTTP servers and never call provider APIs or use real credentials.
