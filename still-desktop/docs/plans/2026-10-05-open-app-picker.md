# Open app picker

The user approved a simple Apps tray picker for currently open desktop windows. Preserve the existing native app positioning, widget system and saved shortcuts.

1. Clicking Apps opens a modal picker; dragging Apps still creates an empty card. The Apps arrow retains saved buttons and exposes Attach open app. The picker includes Open app. Existing Apps cards can use the same picker without choosing an executable first.
2. List app names, window titles and icons, with search and Refresh. Include Still-managed app/browser windows marked Attached and disable duplicate attachment. Small previews are requested explicitly per row; unsupported, minimized, or unresponsive windows show an unavailable state. All metadata and previews remain local.
3. Selecting a window creates an independent Apps card or attaches to the selected existing card. Revalidate HWND and process ID before granting the exact executable and before attachment. Keep HWND/PID instructions only in transient React state, never in saved layouts or presets. Optional Save app to tray records an opaque app grant with a customizable name. Saved-app clicks reuse a single available matching window; multiple matches offer selection, and no match launches the app.
4. Open app uses the existing native app picker and launches into a new Apps panel. Preserve Detach, resizing, workspace visibility, screenshots and document-safe release. Permit renaming and saving from an attached card.

Validation: 53 frontend tests and 27 Rust tests pass. Regressions cover search/attached ordering and transient window identity; saved-app reuse with zero, one or multiple matching windows; safe metadata names; real GDI icon PNG encoding; stale PID and hidden/closed-window rejection before preview. The existing hidden Windows fixture verifies move/resize at 150% scale, clipping and release without closing. TypeScript, production Vite compilation and the Tauri Windows release build pass. One opt-in real Chrome GUI smoke test remains ignored.

The isolated web preview verified tray/card picker entry points, search and save controls, Cancel, saved Apps expansion/collapse, and no console warnings/errors. Desktop actions remain disabled in the web preview. The screenshot at `../../../ver0.18-app-picker-preview.png` is UI evidence only. Native UI control is unavailable, so real Word/third-party listing, live PrintWindow previews and attachment are not claimed as interactively verified.

Manual acceptance: open two Word documents and another desktop app, click Apps, verify names/icons/window titles and search, then attach the intended document. Confirm an Attached badge prevents selecting it again. Rename it, save it in the tray, move/resize/switch workspaces, then Detach and verify its document stays open. A saved button must reuse a single available matching window, ask for explicit selection when several match, and launch when none match. Request a preview; unsupported or unresponsive previews must leave attachment usable. Reopen Still and verify saved layouts/buttons without storing stale handles.

Windows references: [version metadata](https://learn.microsoft.com/en-us/windows/win32/api/winver/nf-winver-verqueryvaluew), [bounded icon messages](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendmessagetimeoutw), [window preview rendering](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-printwindow). PrintWindow can block, so previews run outside the UI thread with bounded waiting and a limit on outstanding render workers.
