## Done

### Native minimum-size defects (app_panel.rs) — C1, C2, C3, C4, C5, C6
The prior code latched whatever `GetWindowRect` returned right after `SetWindowPos` as a permanent, monotonically-increasing floor, and never un-maximized before sampling. Fixes:

- **C1 (false floor):** `position()` now `SW_RESTORE`s a zoomed window (and `SW_SHOWNOACTIVATE`s an iconic one) before sampling, so a maximized/hidden/initializing window cannot latch the monitor size. A measured refusal now requires the SAME oversize on TWO consecutive passes (`pending` -> `measured`) before it becomes the floor.
- **C2 (decrease):** a previously inflated floor now clears. When the user drags below the stored floor, the declared minimum is re-queried, and if the app accepts the smaller requested size the stale `measured`/`declared` floor is dropped so a lower minimum can take effect.
- **C3 (stale scale):** `minimum_scale` is stamped only when a minimum query actually succeeded (at least one dimension returned); a timeout leaves it unstamped so the next pass retries.
- **C4 (fabricated minimum):** `tracking_minimum()` no longer pre-seeds `ptMinTrackSize` with OS track metrics; a window that never writes `WM_GETMINMAXINFO` yields `(None,None)` and no fabricated floor.
- **C5 (DPI):** the floor is stored in PHYSICAL pixels (`declared`/`measured`) and divided by the CURRENT scale in `Info`, so a monitor/DPI change can never leave a stale capture-time CSS value.
- **C6 (comparison):** `required_size` compares the observed size against what Still actually REQUESTED (wanted plus its own floor), not the raw wanted size, so Still's own floor is not misread as an app refusal.

### Frontend floor handling (appPanel.ts, AppsWidget.tsx, platform/appPanel.ts) — C2 frontend half
- `Info`/`AppPanelInfo` gained `measured:boolean`. A valid reported minimum still wins; a `null` with `measured:true` is a CONFIRMED no-floor and clears the cached `appMinWidth`/`appMinHeight`; a `null` with `measured:false` is transient and keeps the saved limit.
- `AppsWidget.sync()` now also calls `fit()` when `info.measured===true`, so a confirmed no-floor un-sticks a stale limit.

### Wider canvas (layout.ts, WorkspaceCanvas.tsx)
- New exported `canvasExtent(viewportWidth, widgets)` = `max(ceil(max(300, viewportWidth)*1.3), furthestWidgetRightEdge+20)`. Extra scrollable room, not zoom; saved placements are never clamped.
- `WorkspaceCanvas` tracks the viewport width reactively (ResizeObserver + state) so sidebar toggles and window resizes recompute the extent; the canvas `minWidth` and the add/preset/group/pickApp placement hints use the extent. Lecture mode still uses the visible viewport width (unchanged), and native clipping still clips to the visible viewport.
